# 日志库扩展计划

## 概述

当前 lg 库已支持基本日志输出（Console/File/Multi/Router）和动态文件名（LogNamePattern）。计划扩展以下能力，全部可插拔、可组合。

## 扩展功能

### 1. 定时切割（RotateByInterval）

按时间间隔自动创建新日志文件，避免单文件过大。

```go
// 每小时切割
lg.SetPath("logs", lg.LevelInfo,
    lg.NewLogNamePattern().Module().Char("_").Date("2006-01-02").Char("_").Clock("15"),
    lg.RotateByInterval(time.Hour),
)

// 每天切割
lg.RotateByInterval(24 * time.Hour)

// 每分钟切割（调试用）
lg.RotateByInterval(time.Minute)
```

实现思路：
- 内部维护一个定时器 goroutine
- 到达间隔时，关闭当前文件，下次 Write 时 LogName 自然产生新文件名
- 可插拔：不传该选项时不做定时切割（仅依赖 LogName 自然切换）

### 2. 文件大小限制（RotateBySize）

单文件超过指定大小时自动切换新文件。

```go
// 超过 100MB 切割
lg.RotateBySize(100 * 1024 * 1024)

// 超过 10MB 切割
lg.RotateBySize(10 << 20)
```

实现思路：
- 每次 Write 后累计字节数
- 超过阈值时关闭当前文件，下次 Write 时切换
- 可与 RotateByInterval 组合（任一条件触发）
- 切换时文件名追加序号：`pg_2026-08-01.001.log`, `pg_2026-08-01.002.log`

### 3. 按日志级别分目录（LevelDir）— 默认功能

**默认行为**：`SetPath` 自动按日志级别分目录，无需额外配置。目录名使用 level 的小写字符串。

```
logs/
├── debug/
│   └── pg_2026-08-01.log
├── info/
│   └── pg_2026-08-01.log
├── warn/
│   └── pg_2026-08-01.log
├── error/
│   └── pg_2026-08-01.log
└── fatal/
    └── pg_2026-08-01.log
```

```go
// 默认：自动按级别分目录
lg.SetPath("logs", lg.LevelDebug,
    lg.NewLogNamePattern().Module().Char("_").Date("2006-01-02"),
)
```

**关闭分级目录**：如果不需要分级，显式关闭。

```go
lg.SetPath("logs", lg.LevelInfo,
    lg.NewLogNamePattern().Module().Char("_").Date("2006-01-02"),
    lg.LevelDirOff(),  // 关闭分级，所有级别写到同一目录
)
```

**自定义目录名**：覆盖默认的目录名映射。

```go
// 自定义 error 和 fatal 合并到 error 目录
lg.SetPath("logs", lg.LevelInfo,
    lg.NewLogNamePattern().Module().Char("_").Date("2006-01-02"),
    lg.LevelDirName(lg.LevelFatal, "error"),  // fatal 也写到 error/
)
```

实现思路：
- `SetPath` 内部根据传入的 level 参数自动创建对应子目录
- 每个 level 对应一个独立的 FileWriter，指向不同子目录
- 底层使用 MultiWriter 组合所有级别的 FileWriter
- 每个级别的 FileWriter 共享同一个 LogNamePattern

### 4. 定时清理（Retention）

定期删除过期日志文件，控制磁盘占用。

```go
// 保留最近 7 天的日志
lg.Retention(7 * 24 * time.Hour)

// 保留最近 30 天，每小时检查一次
lg.Retention(30*24*time.Hour, lg.CheckInterval(time.Hour))

// 按文件数量保留：最多 100 个文件
lg.RetentionMaxFiles(100)

// 按总大小保留：最多 1GB
lg.RetentionMaxSize(1 << 30)
```

实现思路：
- 启动后台 goroutine 定期扫描日志目录
- 按修改时间删除超过保留期的文件
- 或按文件数量/总大小，删除最旧的文件
- 只删除由当前 FileWriter 产生的文件（通过文件名前缀匹配，避免误删）

### 5. 日志级别优先级（LevelPriority）— 已废弃

> `SetPath` 的 `level` 参数已覆盖此需求：
> - `lg.SetPath("logs", lg.LevelWarn, pattern)` → 只输出 warn/error/fatal
> - `lg.SetPath("logs", lg.LevelDebug, pattern)` → 输出全部级别
>
> 无需额外实现。

## API 设计

`SetPath` 签名：`func SetPath(dir string, level Level, pattern *LogNamePattern, opts ...LogOption) error`

```go
// 最简用法
lg.SetPath("logs", lg.LevelInfo,
    lg.NewLogNamePattern().Module().Char("_").Date("2006-01-02"),
)

// 全功能用法
lg.SetPath("logs", lg.LevelInfo,
    lg.NewLogNamePattern().Module().Char("_").Date("2006-01-02"),

    // 分级目录（可选）
    lg.WithLevelDir(lg.LevelError, "error"),

    // 切割策略（可选）
    lg.WithRotateByInterval(time.Hour),
    lg.WithRotateBySize(100 << 20),

    // 清理策略（可选）
    lg.WithRetention(7 * 24 * time.Hour),
)
```

- 所有 Option 独立生效，可任意组合

## 实现优先级

| 优先级 | 功能 | 理由 |
|--------|------|------|
| P0 | LevelDir | 日志分类，便于监控告警 ✅ |
| P0 | RotateByInterval | 定时切割 ✅ |
| P0 | RotateBySize | 防止单文件膨胀 ✅ |
| P1 | Retention | 磁盘空间管理 ✅ |
| ~~P2~~ | ~~LevelPriority~~ | 已被 SetPath level 参数覆盖，废弃 |

## 内部实现要点

- 所有扩展通过 `FileWriter` 内部组合实现，不修改 Writer 接口
- 切割/清理的 goroutine 在 `Close()` 时优雅退出
- 文件名序号使用 `.000` 三位补零格式，兼容字典序排序
- 所有配置通过 `FileWriterOption` 函数传入构造函数
