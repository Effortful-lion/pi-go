## 执行阶段

### 阶段一：基础设施（独立，无互相依赖）

#### 1. Agent: Reset() + Continue() — `agent/agent.go`

```go
// Reset 清空对话历史，开始新对话。保留 system prompt。
func (a *Agent) Reset() {
    a.messages = nil
    if a.cfg.SystemPrompt != "" {
        a.messages = append(a.messages, ai.Message{
            Role: ai.RoleSystem, Content: a.cfg.SystemPrompt,
        })
    }
}

// Continue 注入额外上下文后继续对话，不追加新用户消息。
func (a *Agent) Continue(ctx context.Context, extraContext string) Stream {
    if extraContext != "" {
        a.messages = append(a.messages, ai.Message{
            Role: ai.RoleUser, Content: extraContext,
        })
    }
    return a.Run(ctx, "")
}
```

#### 2. Tool: File Tool — `tool/builtin/file.go`

4 个函数：
- `read_file`：读取文件（path, offset, limit 参数）
- `write_file`：写入文件（path, content 参数）
- `list_dir`：列出目录（path 参数）
- `search_file`：搜索文件（pattern, recursive 参数）

安全考虑：
- `AllowedRoots []string` 限制访问范围
- `MaxFileSize int64` 限制最大读取字节数（默认 1MB）
- 符号链接解析后再比对路径

#### 3. Tool: Shell Tool — `tool/builtin/shell.go`

1 个函数：`shell_exec`

安全考虑：
- `AllowedCommands []string` 白名单（空=允许所有）
- `BlockedPatterns []string` 黑名单（如 `rm -rf`）
- `CmdTimeout time.Duration` 超时（默认 30s）
- 使用 `os/exec` 的 `CommandContext`

#### 4. AI: Anthropic Provider — `ai/providers/anthropic/`

Anthropic Messages API：`POST https://api.anthropic.com/v1/messages`
- 认证头：`x-api-key: <key>` + `anthropic-version: 2023-06-01`
- 流式：`text/event-stream`，与 OpenAI 类似但 event 类型不同
  - `message_start` → `content_block_start` → `content_block_delta` → `content_block_stop`
  - `message_delta`（含 usage）
  - `message_stop`
- 工具定义格式：与 OpenAI 不同，使用 Anthropic 的 `tools` 格式
- system prompt 通过顶层 `system` 字段传递（不是 message）

已知模型列表：`claude-sonnet-4-5`, `claude-haiku-4-5`

#### 5. AI: Gemini Provider — `ai/providers/google/`

Google Gemini API：`POST https://generativelanguage.googleapis.com/v1beta/models/{model}:streamGenerateContent`
- API Key 作为 query param：`?key=<api_key>`
- 流式：数组形式的 SSE `[{"candidates":[...]}]`
- system prompt 通过 `systemInstruction` 字段传递
- 工具声明格式：`functionDeclarations` 数组

已知模型列表：`gemini-2.5-flash`, `gemini-2.5-pro`

### 阶段二：TUI 增强

#### 6. TUI: 历史记录 — `tui/terminal.go` + `tui/chat.go`

- `LineEditor` 结构体增加 `history []string` + `historyIdx int`
- ↑ ↓ 键浏览历史（`[A` `[B` 转义序列）
- `AddHistory(line string)` 方法，自动去重
- `ChatUI.Run()` 中每次提交后调用 `AddHistory`
- 历史上限 1000 条

#### 7. TUI: 多行输入 Alt+Enter — `tui/terminal.go`

- `EditLine` 改为处理 `[][]rune`（多行 lines 数组）
- Alt+Enter（`\033\r` 或 `\033\n`）在当前光标位置插入 `\n`
- 多行编辑渲染：每行独立计算光标位置
- 返回值 `string` 自然包含 `\n`

#### 8. TUI: Ctrl+L 清屏 — `tui/terminal.go`

- 在 `readKey` 后增加判断 `Ctrl+L`（ASCII 12）
- 调用 `ClearScreen()` 并重新绘制 prompt + input

#### 9. TUI: 语法高亮 — `tui/highlight.go`（新文件）

- 不引入 chroma 库，自己实现极简高亮（Go/Python/JS/Shell/JSON/YAML）
- `Highlight(code string, lang string) string` → ANSI 着色文本
- 关键词着色 + 字符串着色 + 注释着色
- 在流式场景下判断当前是否在 ``` 代码块内

#### 10. TUI: Markdown 渲染 — `tui/markdown.go`（新文件）

- 不引入 glamour，自己实现轻量级终端 Markdown
- 支持元素：`# Heading`, `**bold**`, `*italic*`, `` `code` ``, `- list`, `> quote`, `| table |`
- 流式友好：逐行处理，不等待完整文档
- `RenderMarkdown(text string) string` → ANSI 样式文本

#### 11. TUI: 文件路径粘贴 — `tui/terminal.go`

- 在输入过程中检测粘贴的路径（以 `/`、`./`、`~/` 开头）
- `os.Stat` 判断文件是否存在，存在则高亮（青色）

#### 12. TUI: Tab 补全 — `tui/terminal.go`

- Tab 键触发文件名/路径自动补全
- `completePath(prefix string) string` 查找匹配的文件
- 多个匹配时显示候选列表

#### 13. TUI: 对话导出 — `tui/chat.go`

```go
func (ui *ChatUI) ExportConversation(path string) error
```
- 将对话历史（agent.messages）导出为 Markdown 文件
- 格式：`## role` + 内容块

### 阶段三：CLI 产品增强

#### 14. CLI: 配置文件 — `cmd/pi/config.go`（新文件）

- YAML 格式，支持 `~/.pi-go/config.yaml` 和 `./.pi-go.yaml`
- Config 结构体包含：Provider, Model, APIKey, BaseURL, SystemPrompt, MaxSteps, Temperature, MaxTokens
- 参数优先级：命令行 > 环境变量 > 配置文件 > 默认值
- `gopkg.in/yaml.v3` 依赖

#### 15. CLI: 子命令系统 — `cmd/pi/` 重构

```
cmd/pi/
├── main.go         # 命令路由
├── chat.go         # pi chat（默认命令）
├── config_cmd.go   # pi config init/show/set
```

- `pi chat` / `pi`（默认）→ 启动对话
- `pi config init` → 生成 `~/.pi-go/config.yaml`
- `pi config show` → 显示当前配置
- `pi version` → 版本信息
- `pi help` → 命令手册

#### 16. CLI: Session 持久化 — `agent/session.go` + `cmd/pi/`

```
agent/session.go
- Session 结构体：io.Writer, 追加写入 JSONL
- Session.WriteMessage(msg ai.Message)
- Session.Load(path) 读取历史
- Session.Record() 返回所有消息
```
- JSONL 格式存储到 `~/.pi-go/sessions/`
- 每次消息实时追加写入
- `pi chat --continue` 恢复上次对话
- `pi chat --session <name>` 恢复指定对话

## 风险与注意事项

1. **Shell Tool 安全问题**：黑名单 `rm -rf`, `sudo`, `chmod 777`, `curl | sh`，白名单模式可选
2. **Anthropic/Gemini 的消息格式差异**：需要仔细处理 tool_result 的回溯方式
3. **多行输入重构**：`EditLine` 从单行 `[]rune` 改为多行 `[][]rune`，影响面较大，需确保现有单行编辑不受影响
4. **Markdown/高亮的流式渲染**：不完整的 Markdown 语法（如未闭合的 ```）需要做状态追踪
5. **配置文件侵入**：`flag` + YAML 两层参数源需要统一到一处
