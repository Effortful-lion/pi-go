## 扩展项

### P0 — Anthropic Provider

**描述**：新增 Anthropic（Claude）系列模型的 Provider 实现。

**为什么需要**：
- Claude 在代码生成、长上下文场景下与 GPT 形成互补
- pi-agent 需要多提供商支持才能算真正的"多提供商"库

**实现要点**：
- Anthropic Messages API 使用 `text/event-stream`，与 OpenAI 的 SSE 类似
- 差异点：消息格式（`content` 是数组）、工具定义格式略有不同、usage 结构不同
- 也可能用 Anthropic 官方 Go SDK，但更倾向用标准库直接 HTTP 实现（与 OpenAI Provider 一致）

**文件变更**：
```
ai/providers/anthropic/
├── provider.go          # Anthropic Provider 实现
└── provider_test.go     # mock SSE 测试
```

**依赖**：无新依赖（AI 层接口已完备）

### P1 — Google Gemini Provider

**描述**：新增 Google Gemini 系列模型的 Provider 实现。

- 差异点：system prompt 通过 `systemInstruction` 字段传递、工具声明格式不同、多模态支持更原生

**文件变更**：

### P2 — [待考虑]Provider 自动注册与发现

**描述**：支持通过 import 副作用自动注册 Provider，类似 `database/sql` 的 driver 注册模式。

**为什么需要**：
- 当前需要手动 `import openai` 再 `openai.New()`，无法通过字符串名创建
- CLI 参数 `-provider anthropic` 需要一种机制将字符串映射到 Provider 构造函数

**实现思路**：
```go
// ai/registry.go
var registry = map[string]func(Config) Provider{}

func Register(name string, factory func(Config) Provider) {
    registry[name] = factory
}

func New(name string, cfg Config) (Provider, error) {
    factory, ok := registry[name]
    if !ok {
        return nil, fmt.Errorf("unknown provider: %s", name) // 需要已 import 对应包
    }
    return factory(cfg), nil
}

// ai/providers/openai/init.go
func init() {
    ai.Register("openai", func(cfg ai.Config) ai.Provider {
        return New(Config{APIKey: cfg.APIKey, BaseURL: cfg.BaseURL})
    })
}
```

**文件变更**：
```
ai/registry.go          # 新增：注册表
ai/providers/openai/init.go    # 新增：OpenAI 注册
```

### P2 — [待考虑]流式处理优化

**描述**：优化 SSE 解析性能，减少内存分配。

**当前状态**：
- 每个 SSE chunk 做一次 `json.Unmarshal`，产生 GC 压力
- 工具调用 arguments 需要手动拼接再解码

**优化方向**：
- 使用 `sync.Pool` 复用 SSE chunk 结构体
- 使用 `json.Decoder` + `Token` 流式解码，减少中间分配

---

### P2 — [待考虑]请求重试与错误恢复

**描述**：对可恢复的错误（429 rate limit、5xx 服务端错误）实现指数退避重试。

**实现要点**：
- 可配置的重试策略（最大重试次数、退避因子）
- 在 Provider 级别统一处理，不在 Model 级别重复实现
