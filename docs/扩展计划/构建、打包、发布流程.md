# 构建、打包、发布流程

## 概述

为 pi-go 项目设计一套**企业级但轻量**的构建-打包-发布流程，模仿真实开源项目的发布实践（如 lazygit、fzf、gh CLI）。

核心原则：
- **零额外依赖**：只依赖 Go 工具链 + GitHub Actions
- **一次配置，永久生效**：通过 Git Tag 触发，自动构建多平台二进制
- **用户友好**：提供 `curl | bash` 一键安装、Homebrew、go install 三种方式

---

## 一、版本策略

遵循 [Semantic Versioning](https://semver.org/)：

```
v1.0.0  → 首个稳定版
v1.1.0  → 新增功能（向后兼容）
v1.1.1  → Bug 修复
v2.0.0  → 破坏性变更
```

版本号来源：
- **开发阶段**：`cmd/pg/main.go` 中的 `const version = "1.0.0"` 作为源码版本
- **发布阶段**：Git Tag `v1.0.0` 触发 CI，通过 `ldflags` 注入版本号到二进制

## 二、构建方案

### 2.1 目标平台矩阵

Go 交叉编译零成本，支持以下平台（覆盖 99% 用户）：

| OS | Arch | 典型用户 |
|----|------|---------|
| linux | amd64 | Linux 桌面/服务器 |
| linux | arm64 | Apple Silicon Linux、树莓派 |
| darwin | amd64 | Intel Mac |
| darwin | arm64 | Apple Silicon Mac |
| windows | amd64 | Windows 桌面 |

共 5 个平台，编译时间约 30 秒。

### 2.2 ldflags 注入

编译时注入元信息，`pg version` 输出完整版本详情：

```bash
go build -ldflags "
    -X main.version=v1.0.0
    -X main.commit=$(git rev-parse --short HEAD)
    -X main.buildDate=$(date -u +%Y-%m-%dT%H:%M:%SZ)
" -o pg ./cmd/pg/
```

输出示例：
```
$ pg version
pg version v1.0.0
commit:  abc1234
built:   2026-08-01T12:00:00Z
go:      go1.26.5
```

### 2.3 构建产物命名

参考 Go 社区惯例：`{binary}_{os}_{arch}.tar.gz`

```
pg_1.0.0_darwin_amd64.tar.gz
pg_1.0.0_darwin_arm64.tar.gz
pg_1.0.0_linux_amd64.tar.gz
pg_1.0.0_linux_arm64.tar.gz
pg_1.0.0_windows_amd64.zip
```

每个压缩包内只含一个二进制文件和 LICENSE：

```
pg_1.0.0_darwin_arm64.tar.gz
├── pg          # 可执行文件
└── LICENSE     # MIT 许可证
```

## 三、发布流程

### 3.1 触发方式

推送 Git Tag 即触发发布：

```bash
# 1. 更新版本号
# 编辑 cmd/pg/main.go: const version = "1.0.1"

# 2. 提交并打 Tag
git add cmd/pg/main.go
git commit -m "release: v1.0.1"
git tag v1.0.1

# 3. 推送（CI 自动构建 + 发布）
git push origin main --tags
```

### 3.2 GitHub Actions Release 流程

```
Git Tag (v1.0.1) 推送
    │
    ├─ CI (lint + test)  ← 先跑，确保代码质量
    │
    └─ Release Job:
        ├─ 交叉编译 5 个平台
        ├─ 生成 checksums.txt
        ├─ 创建 GitHub Release
        ├─ 上传 5 个 tar.gz/zip
        └─ 上传 checksums.txt
```

### 3.3 Release Notes 自动生成

从 commit history 自动生成 changelog（基于 conventional commits）：

```markdown
## v1.0.1 (2026-08-01)

### Features
- feat(ai): 新增 Anthropic Provider 支持

### Bug Fixes
- fix(tui): 修复光标定位问题

### Downloads
| Platform | File |
|----------|------|
| macOS (Apple Silicon) | pg_1.0.1_darwin_arm64.tar.gz |
| macOS (Intel) | pg_1.0.1_darwin_amd64.tar.gz |
| Linux (x86_64) | pg_1.0.1_linux_amd64.tar.gz |
| Linux (ARM64) | pg_1.0.1_linux_arm64.tar.gz |
| Windows (x86_64) | pg_1.0.1_windows_amd64.zip |
```

## 四、用户安装方式

提供 3 种安装方式，覆盖不同用户偏好：

### 方式 1：curl | bash 一键安装（推荐）

```bash
curl -fsSL https://raw.githubusercontent.com/Effortful-lion/pi-go/main/install.sh | bash
```

脚本自动检测 OS/Arch，下载对应二进制，安装到 `$GOPATH/bin` 或 `/usr/local/bin`。

### 方式 2：go install

```bash
go install github.com/Effortful-lion/pi-go/cmd/pg@latest
```

Go 开发者首选，自动编译。

### 方式 3：Homebrew（未来）

```bash
brew install Effortful-lion/tap/pg
```

需要创建 [Homebrew Tap](https://docs.brew.sh/Taps) 仓库，维护 Formula。

### 方式 4：手动下载

从 GitHub Releases 页面下载对应平台的 tar.gz，解压后放到 PATH。

## 五、CI 配置设计

### 5.1 工作流拆分

```
.github/workflows/
├── ci.yml        # 每次 push/PR: lint + test
└── release.yml   # Git Tag: build + package + publish
```

`ci.yml` 已实现，`release.yml` 需新建。

### 5.2 release.yml 核心逻辑

```yaml
name: Release

on:
  push:
    tags: ['v*']

jobs:
  goreleaser:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-go@v5
        with: { go-version: '1.23' }
      - uses: goreleaser/goreleaser-action@v6
        with: { version: latest, args: release --clean }
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

### 5.3 .goreleaser.yaml 配置

```yaml
version: 2

builds:
  - main: ./cmd/pg
    binary: pg
    goos: [linux, darwin, windows]
    goarch: [amd64, arm64]
    ldflags:
      - -s -w
      - -X main.version={{.Version}}
      - -X main.commit={{.Commit}}
      - -X main.buildDate={{.Date}}

archives:
  - format: tar.gz
    name_template: "{{ .ProjectName }}_{{ .Version }}_{{ .Os }}_{{ .Arch }}"
    format_overrides:
      - goos: windows
        format: zip
    files:
      - LICENSE

checksum:
  name_template: 'checksums.txt'

changelog:
  sort: asc
  filters:
    exclude:
      - '^docs:'
      - '^test:'
      - '^ci:'
```
