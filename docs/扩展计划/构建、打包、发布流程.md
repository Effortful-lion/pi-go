# 构建、打包、发布流程

## 概述

企业级但轻量的构建-打包-发布方案，通过 Git Tag 触发，自动交叉编译 + GitHub Release。

---

## 一、版本策略

[Semantic Versioning](https://semver.org/)：`v1.0.0` → `v1.1.0`（功能） → `v1.1.1`（修复）

---

## 二、构建方案

### 2.1 平台矩阵

| OS | Arch | 说明 |
|----|------|------|
| darwin | arm64 | Apple Silicon Mac ✅ |
| windows | amd64 | Windows 桌面 ✅ |

> 文档保留全平台参考：`linux/amd64` `linux/arm64` `darwin/amd64` 按需扩展。

### 2.2 ldflags 注入

编译时注入版本元信息：

```bash
go build -ldflags "
    -s -w
    -X main.version=v1.0.0
    -X main.commit=$(git rev-parse --short HEAD)
    -X main.buildDate=$(date -u +%Y-%m-%dT%H:%M:%SZ)
" -o pg ./cmd/pg/
```

`pg version` 输出：

```
pg version v1.0.0
  commit:    abc1234
  built:     2026-08-01T12:00:00Z
  go:        go1.26.5
```

`cmd/pg/main.go` 中 `version`/`commit`/`buildDate` 是 `var`（非 `const`），默认值 `"dev"`/`"none"`。

### 2.3 产物命名

```
pg_1.0.0_darwin_arm64.tar.gz
pg_1.0.0_windows_amd64.zip
```

## 三、新增文件

### 3.1 `.goreleaser.yaml`

goreleaser 配置，核心内容：

- `builds.goos: [darwin, windows]`，`goarch: [amd64, arm64]`，`ignore` 排除 `darwin/amd64` 和 `windows/arm64`
- `ldflags: -s -w -X main.version={{.Version}} ...`
- `archives` 打包 tar.gz/zip，附带 LICENSE
- `checksums.txt` 校验文件
- `changelog` 自动从 commit 生成（排除 docs/test/ci）

### 3.2 `.github/workflows/release.yml`

```yaml
name: Release
on: push: { tags: ['v*'] }
jobs:
  goreleaser:
    steps:
      - checkout + setup-go
      - goreleaser/goreleaser-action@v6 (args: release --clean)
```

### 3.3 `LICENSE`

MIT 许可证。

### 3.4 `install.sh`

自动检测 OS/Arch，从 GitHub Releases 下载预编译二进制到 `$GOPATH/bin`。

```bash
curl -fsSL https://raw.githubusercontent.com/Effortful-lion/pi-go/main/install.sh | bash
```

## 四、发布流程

**版本号唯一来源是 git tag**，不在代码中硬编码。goreleaser 通过 ldflags 自动注入 `{{.Version}}`。

### 4.1 确定版本号

```bash
# 查看最新 tag，人判断 bump 哪一位
git tag --sort=-v:refname | head -1
# 输出: v1.0.0 → 下一个可以是 v1.0.1 (fix)、v1.1.0 (feat)、v2.0.0 (breaking)
```

| 变更类型 | bump | 示例 |
|---------|------|------|
| Bug 修复 | patch | v1.0.0 → v1.0.1 |
| 新功能（向后兼容） | minor | v1.0.0 → v1.1.0 |
| 破坏性变更 | major | v1.0.0 → v2.0.0 |

### 4.2 发布操作

```bash
git tag v1.0.1
git push origin main --tags
```

Git 不允许重复 tag，无需担心覆盖。

```
Tag 推送
  └─ Release Job:
       ├─ goreleaser 交叉编译 2 平台（ldflags 注入 tag 为版本号）
       ├─ 打包 tar.gz/zip + checksums.txt
       ├─ 创建 GitHub Release（含自动 changelog）
       └─ 上传构建产物
```

本地开发构建不注入版本号时，`pg version` 输出 `dev`。

## 六、Makefile

统一开发/构建/发布命令入口，`make help` 查看全部。

| 分组 | 命令 | 说明 |
|------|------|------|
| 编译打包发布 | `build` → `pack` → `release` | 本地构建 → 手动打包 → 推送 tag 触发 CI |
| 代码检查 | `lint` → `test` | golangci-lint → 全量测试 + race |
| 版本管理 | `version` → `next-version` | 查看最新 tag → 交互式打新 tag |
| 其他 | `run` / `clean` / `help` | 本地运行 / 清理 / 帮助 |

## 七、文件清单

```
pi-go/
├── .github/workflows/
│   ├── ci.yml              # lint + test
│   └── release.yml         # Git Tag → goreleaser → GitHub Release
├── .goreleaser.yaml        # goreleaser 配置
├── .gitignore              # 编译产物 + OS 文件
├── Makefile                # 开发/构建/发布统一入口
├── pack.sh                 # 本地手动打包（不依赖 CI）
├── LICENSE                 # MIT
├── install.sh              # 一键安装（OS/Arch 检测）
├── uninstall.sh            # 卸载
└── cmd/pg/
    ├── main.go             # 公共代码 (printVersion/printHelp)
    ├── main_unix.go        # Unix 子命令路由
    ├── main_windows.go     # Windows 子命令路由
    └── chat.go             # chat 命令 (!windows)
```
