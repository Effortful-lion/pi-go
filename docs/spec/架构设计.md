# 架构设计

## AI 层（`ai/`）

### 概述

提供多提供商 LLM 统一接口，将 OpenAI、Anthropic、Google 等差异抽象为统一接口。

### 架构分层

```
agent 层 → ai 层 → lg 层
```

### 核心类型

**Message 消息体系**：单一 `Message` struct + `Role` 字段区分类型，不用 interface union。

```go
type Role string  // system / user / assistant / tool
type Message struct { Role; Content; Blocks []ContentBlock; ToolCallID; ToolName }
```

**ContentBlock**：flat struct + `Type` 字段（text/thinking/tool_call/image），用于 AssistantMessage 富文本。

**Context 对话上下文**：`Messages []Message` + `Tools []ToolDefinition` + `SystemPrompt/MaxTokens/Temperature`。

**事件系统**：模仿 SSE 流式响应生命周期。`EventType` 枚举（Start/TextStart/TextDelta/TextEnd/ThinkingStart/ThinkingDelta/ThinkingEnd/ToolCallStart/ToolCallDelta/ToolCallEnd/Done/Error），通过 Go channel 传输。

**Provider 接口**：`ID() / Name() / Models() / Model(id) / Chat(ctx, modelID, context) Stream`

### 设计决策

- **channel 而非回调**：Go channel 天然流式管道，for-range 消费
- **flat struct 而非 interface union**：Go 风格，避免类型断言泛滥
- **零外部依赖**：仅 `net/http` + `encoding/json` + `bufio`
- **Provider 管理 Models**：不需要单独的 Models 聚合器

### 文件结构

```
ai/
├── types.go          # Message, ContentBlock, ToolDefinition, Context
├── event.go          # EventType, Event, Stream, Usage
├── model.go          # ModelInfo, Model 接口
├── provider.go       # Provider 接口
└── providers/
    ├── openai/       # OpenAI + 兼容协议
    ├── anthropic/    # Claude Messages API
    └── google/       # Gemini API
```

## Agent 运行时层（`agent/`）

### 概述

在 AI 层之上构建工具调用循环、状态管理和事件驱动的 Agent 运行时。

核心职责：**管理 LLM ↔ 工具调用的自动循环，直到 LLM 给出最终回答**。

### 架构分层

```
cmd/pg → agent → ai → lg
          agent → tool
```

### 核心设计

**Tool 接口**（`tool/tool.go`）：`Name() / Definition() / Execute(ctx, args)`

**Agent 事件系统**：`AgentEventType`（StepStart/StepEnd/ToolCall/ToolResult/TextDelta/Done/Error），比 `ai.Event` 更高层。

**Agent 核心**：`Config{Provider, ModelID, SystemPrompt, Tools, MaxSteps, Temperature, MaxTokens}` → `New() → Run(ctx, userInput) Stream`

**Run 循环逻辑**：
```
1. 用户消息入队
2. for step ≤ maxSteps:
   a. 发送 StepStart
   b. 构造 ai.Context → 调用 provider.Chat()
   c. 消费 ai.Event 流：
      - TextDelta → 透传 AgentTextDelta
      - ToolCall → 累积工具调用列表
      - Done → 发送 StepEnd（Usage）
      - Error → 发送 AgentError，结束
   d. 如果有工具调用 → 执行 → 注入结果 → 继续循环
   e. 如果无工具调用 → 保存 AssistantMessage → Done
3. 超 maxSteps → AgentError
```

**对话历史管理**：Agent 持有 `messages []ai.Message`，每次 `Run()` 不重置历史。工具调用结果注入历史，LLM 可见。

### 与 TypeScript 版差异

| 方面 | TS 版 | Go 版 |
|------|-------|-------|
| 工具调用 | event callback 驱动 | Tool 接口 + Execute，agent 主动调用 |
| 状态管理 | AgentState 独立对象 | Agent.messages 内置 |
| 事件系统 | EventEmitter subscribe | Go channel 流式消费 |
| 循环控制 | AgentLoop 独立组件 | Run() 内 for 循环 |

### 文件结构

```
agent/
├── agent.go          # Agent 结构体 + Run 循环
├── event.go          # AgentEventType, AgentEvent, Stream
├── session.go        # Session 持久化
└── agent_test.go     # mock 测试

tool/
├── tool.go           # Tool 接口
└── builtin/          # File/Shell 内置工具
```

## TUI 层（`tui/`）

### 概述

提供交互式对话所需的终端能力。核心目标：**用最小代价构建"能用、好看"的终端对话界面**。

### 架构分层

```
cmd/pg → tui → agent → ai → lg
```

### 核心模块

**终端底层（`terminal.go`）**：
- Raw Mode（syscall termios，仅 Unix，`//go:build !windows`）
- 光标控制（CursorUp/Down/Forward/Back/Show/Hide）
- 颜色/样式（Style{Fg, Bg, Bold, Dim, Italic, Underline}）
- LineEditor 多行编辑器：多行输入、历史记录（↑↓）、`Ctrl+L` 清屏、`Tab` 路径补全

**ChatUI（`chat.go`）**：
- 交互循环：prompt → 读取输入 → agent.Run() → 消费 AgentEvent 流
- 流式渲染：`AgentTextDelta` 实时写入终端
- Markdown 渲染：标题、粗体、斜体、代码、列表 → ANSI 终端样式
- 对话内命令：`/clear` `/reset` `/export` `/help`

**语法高亮（`highlight.go`）**：Go/Python/JS/Shell/JSON/YAML

**Markdown 渲染（`markdown.go`）**：`MarkdownLine()` 单行转换 + `RenderMarkdown()` 全文转换

### 设计决策

- **放弃组件系统**：pi-agent 只需要对话界面，不是通用 TUI 框架
- **行式追加而非差异渲染**：简化实现，够用即可
- **纯 Go 标准库 + syscall**：零外部依赖
- **`//go:build !windows`**：Windows 不支持 raw mode，通过 build tag 隔离

### 文件结构

```
tui/
├── terminal.go        # ANSI + raw mode + LineEditor
├── chat.go            # ChatUI 交互对话
├── highlight.go       # 语法高亮
├── markdown.go        # Markdown → ANSI
├── box.go             # Unicode 框线工具
├── terminal_test.go   # ANSI 测试
└── chat_test.go       # ChatUI 测试
```

## CLI 产品入口（`cmd/pg/`）

### 概述

将 ai/agent/tui 三个库层组装成可执行的 CLI 产品 `pg`。

### 架构

```
cmd/pg/main.go → ai/providers/ + agent/ + tui/
```

### 命令行

| 命令 | 说明 |
|------|------|
| `pg` / `pg chat` | 启动交互式对话 |
| `pg config init/show/set` | 配置管理 |
| `pg version` | 版本信息 |
| `pg help` | 帮助 |

### 参数优先级

命令行参数 > 环境变量 > YAML 配置文件 > 默认值

### 配置文件（YAML）

`~/.pi-go/config.yaml`，三级优先级。`pg config init` 创建默认配置。

### 版本号

ldflags 注入：`-X main.version={{.Version}} -X main.commit={{.Commit}} -X main.buildDate={{.Date}}`

### 文件结构

```
cmd/pg/
├── main.go            # 公共代码（printVersion/printHelp/main/initLogging）
├── main_unix.go       # Unix 子命令路由（!windows）
├── main_windows.go    # Windows 子命令路由
├── chat.go            # chat 命令（!windows）
├── config.go          # 配置结构体 + YAML
└── config_cmd.go      # config 子命令
```
