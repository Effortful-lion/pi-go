# 终端换行问题

## 问题描述

在 TUI 交互式输入中，希望支持多行输入并区分"换行"与"提交"。需要一种**所有终端 100% 通用**的方案，不依赖特定终端厂商的私有协议。

## 方案演进

### 方案 A：kitty keyboard protocol（已废弃）

通过启用 kitty keyboard protocol 让终端上报 Shift+Enter 修饰键，区分普通 Enter 与 Shift+Enter。

**废弃原因**：macOS 自带 Terminal.app 不支持该协议，无法做到 100% 通用。

### 方案 B：Double Enter（已废弃）

Enter 换行，连续两个空行触发提交。

**废弃原因**：无法在文本末尾插入任意数量的空行，每次按 Enter 到第二个空行就会误提交。

### 方案 C：Bubbletea + Esc 提交（当前方案）

换用 [Bubbletea](https://github.com/charmbracelet/bubbletea) TUI 框架 + [Bubbles/Textarea](https://github.com/charmbracelet/bubbles/textarea) 组件，使用 **Enter 换行 + Esc 提交** + **Bracketed Paste 防粘贴误触发**。

## 技术栈

| 组件 | 包 | 用途 |
|------|-----|------|
| TUI 框架 | `github.com/charmbracelet/bubbletea` | Go 生态最成熟的 TUI 响应式框架，天生支持终端 Raw Mode 和转义序列解析 |
| 文本框 | `github.com/charmbracelet/bubbles/textarea` | 多行文本编辑组件，负责 Buffer 管理、光标移动、文本选区 |
| 样式 | `github.com/charmbracelet/lipgloss` | 光标行背景色等样式定制 |

## 交互逻辑

### Enter 换行 + Esc 提交

1. 用户输入文本，按下 **Enter** 仅插入 `\n` 换行
2. 支持任意数量的换行（包括连续空行）
3. 按下 **Esc** 触发提交

```
用户操作：
  "hello world"  ← Enter 换行
  "line 2"       ← Enter 换行
  ""             ← Enter 换行（空行）
  ""             ← Enter 换行（又一个空行）
  "line 5"       ← Esc 提交！
```

### Bracketed Paste 防粘贴误触发

现代终端在开启 **Bracketed Paste** 后，粘贴操作会被包裹：

```
\x1b[200~    ← 粘贴开始
粘贴的文本内容（可能包含多行和空行）
\x1b[201~    ← 粘贴结束
```

**重要**：`tea.PasteMsg` 在设计中作为概念出现，但当前使用的 bubbletea 版本中该消息类型不存在。实际实现中，Bubbletea 通过 `tea.KeyMsg.Paste` 布尔字段来标识粘贴事件。

**防误触机制**：`Update()` 中检测 `msg.Paste == true` 时，直接将 `tea.KeyMsg` 透传给 Textarea，**不经过 `handleKeyMsg` → `handleEnter` 的判定逻辑**，从而避免粘贴内容中的换行符被误判为提交。

## 架构设计

### 可插拔输入策略（InputStrategy）

为避免将特定交互模式硬编码到 TUI 框架中，将"换行"与"提交"的判定逻辑抽象为 `InputStrategy` 接口：

```go
type InputStrategy interface {
    ShouldSubmit(msg tea.KeyMsg, textareaValue string, running bool) bool
    ShouldInsertNewline(msg tea.KeyMsg, running bool) bool
    HelpText() string
}
```

| 实现 | 行为 |
|------|------|
| `EscSubmitStrategy`（默认） | Enter → 换行，Esc → 提交 |
| 自定义（库使用者实现） | Enter → 直接提交（单行模式）、Ctrl+Enter → 提交等 |

**侵入性分析**：`InputStrategy` 仅被 `ChatModel.handleKeyMsg` 引用，ChatModel 通过 `NewChatModel(ag, resolver, strategy)` 注入，ChatUI 通过 `WithInputStrategy()` option 透传。默认使用 `EscSubmitStrategy`，传 `nil` 自动回退。库使用者无需修改 tui 包代码即可替换交互模式。

### 文件组织

| 文件 | 职责 |
|------|------|
| `tui/model.go` | ChatModel Bubbletea Model 定义，Init/Update/View + 按键路由 + handlePaste/handleSubmit + 历史浏览 + 斜杠命令 |
| `tui/input.go` | InputStrategy 接口定义 + EscSubmitStrategy 默认实现 |
| `tui/stream.go` | Agent Stream → Bubbletea Cmd 适配层，waitForStream/handleStream + flushLine/flushInline 行缓冲 |

| `tui/terminal.go` | 颜色样式函数（Green/Bold/Dim/Red 等）+ ClearScreen + esc 常量（删除约 800 行旧代码） |

### Bubbletea 消息循环

### 关键消息处理

```go
func (m *ChatModel) Update(msg tea.Msg) (tea.Model, tea.Cmd) {
    switch msg := msg.(type) {
    case tea.WindowSizeMsg:
        m.width = msg.Width
        m.height = msg.Height
        m.textarea.SetWidth(msg.Width)
        return m, nil

    case tea.KeyMsg:
        if msg.Paste {
            // 粘贴事件：直接写入 textarea，不触发 Enter 逻辑
            return m.handlePaste(msg)
        }
        return m.handleKeyMsg(msg)

    case streamMsg:
        // Agent 流式事件
        return m.handleStream(msg, m.stream)

    case streamDoneMsg:
        // 流结束
        m.running = false
        m.stream = nil
        return m, nil
    }

    // 其他消息透传给 textarea
    var cmd tea.Cmd
    m.textarea, cmd = m.textarea.Update(msg)
    return m, cmd
}
```

### 按键处理（通过 InputStrategy 解耦）

```go
func (m *ChatModel) handleKeyMsg(msg tea.KeyMsg) (tea.Model, tea.Cmd) {
    // 通过 InputStrategy 判断是否提交
    if m.inputStrategy.ShouldSubmit(msg, m.textarea.Value(), m.running) {
        return m.handleSubmit(m.textarea.Value())
    }

    // 通过 InputStrategy 判断是否插入换行
    if m.inputStrategy.ShouldInsertNewline(msg, m.running) {
        var cmd tea.Cmd
        m.textarea, cmd = m.textarea.Update(tea.KeyMsg{Type: tea.KeyEnter})
        return m, cmd
    }

    // ... Ctrl+C/D/L, ↑↓ 等通用按键
}
```

### EscSubmitStrategy（默认实现）

```go
type EscSubmitStrategy struct{}

func (s EscSubmitStrategy) ShouldSubmit(msg tea.KeyMsg, _ string, running bool) bool {
    return !running && msg.Type == tea.KeyEsc
}

func (s EscSubmitStrategy) ShouldInsertNewline(msg tea.KeyMsg, running bool) bool {
    return !running && msg.Type == tea.KeyEnter
}

func (s EscSubmitStrategy) HelpText() string {
    return Dim("Enter: newline | Esc: send | Ctrl+C: quit")
}
```

### Agent Stream 适配

```
agent.Stream (channel)  ──▶  waitForStream()  ──▶  streamMsg  ──▶  handleStream()
                                    │                                    │
                                    │  channel 关闭                      │  EventDone/EventError → 停止
                                    ▼                                    ▼
                              streamDoneMsg                        m.running = false
```

```go
// waitForStream 将 agent.Stream (channel) 适配为 Bubbletea Cmd
func waitForStream(stream agent.Stream) tea.Cmd {
    return func() tea.Msg {
        evt, ok := <-stream
        if !ok {
            return streamDoneMsg{}
        }
        return streamMsg(evt)
    }
}

// handleStream 处理事件：EventTextDelta → 行缓冲累积 → flushLine 渲染
// EventToolCall/EventToolResult → 缩进显示工具信息
// EventStepEnd → 显示 token 用量
// EventError → 停止流并显示错误
// EventDone → 停止流
```

### View 渲染策略

- **对话历史输出**：使用 `strings.Builder` 累积所有渲染后的 ANSI 字符串，`View()` 时直接 `WriteString`
- **输入区域**：Agent 运行时隐藏输入框（`!m.running`），避免干扰流式输出
- **渲染工具函数**：复用原有的 `MarkdownLine()`、颜色样式函数（`Green`/`Bold`/`Dim`/`Red` 等）
- **Textarea 样式**：`FocusedStyle.CursorLine` 设置深灰色背景（`#236`），提供光标行阴影效果
- **Textarea 配置**：`Prompt = "> "`，无 Placeholder，`SetHeight(10)` 保证多行阴影覆盖

## 为什么用 Esc 而不是 Double Enter

| 方案 | 多空行支持 | 粘贴安全 | 学习成本 |
|------|-----------|---------|---------|
| Double Enter（已废弃） | 不支持（第二个空行就提交） | 需要 Bracketed Paste 防护 | 低（直觉） |
| Esc 提交（当前） | 支持任意数量空行 | Bracketed Paste 双重保险 | 低（Esc=发送，类似聊天应用） |

**选型原因**：Double Enter 方案下用户无法在文本末尾插入任意数量的连续空行，这是致命缺陷。Esc 方案无此限制，且 Bracketed Paste 机制天然防止粘贴内容中的空行误触发。

## 方案优势

1. **100% 跨平台**：Windows Terminal、macOS Terminal.app、iTerm2、Linux SSH、VS Code/Cursor 内置终端全部无需配置即可运行
2. **防粘贴误触发**：Bracketed Paste 机制天然隔离粘贴事件与按键事件，通过 `tea.KeyMsg.Paste` 字段识别
3. **任意多空行**：Esc 提交方案无空行数量限制，用户可自由编排多行输入
4. **成熟的组件**：Bubbletea + Bubbles/Textarea 是 Go 生态最成熟的 TUI 组合，社区活跃、文档完善
5. **保留渲染能力**：MarkdownLine、颜色样式等渲染工具函数完整保留，不引入额外依赖
